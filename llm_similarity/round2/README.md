# Similarity measurement, round 2 — contexts × category vignettes

**Goal (NG's ask, 2026-07-19).** Round 1 (May, now Table 3) measured story↔game *structural*
similarity: it covers only the story lever and only similarity to game forms. Round 2 measures the
similarity of **all our contexts** — the two stories AND the Market/Control descriptions of each
game — to **categories of representations**: the weight categories used in the classification
(Moral, Self-interest, Mutual Benefit/Cooperation) and the receiver types (accepting/rejecting in
UG, returning/keeping in TG), which are the belief component. This is the input eq. (retrieval)
runs on, and it ties both treatments to representations.

**Approach (SN-approved, 2026-07-19).** The vignette design from the NG conversation notes:
categories enter not as abstract definitions but as **sets of concrete situations** (vignettes)
generated by an LLM from the category definitions — because the theory's categories are classes of
situations, and similarity-to-exemplars is the Tversky-style object. Pipeline:

1. **Generate** (once, frozen): a generator conversation produces 24 sender-side vignettes
   (8 per category, domains balanced across categories) + 8 receiver-type vignettes
   (2 × accepting / 2 × rejecting for UG; 2 × returning / 2 × keeping for TG).
   Prompt: `01_generator_prompt.md`. Output frozen in `vignettes.md`.
2. **Rate** (blind): 3 frontier models × 3 label permutations = 9 fresh conversations
   (the May protocol). Raters see vignettes as V1–V32 and contexts as TEXT A–J in permuted
   order, with no category information. Prompts: `02_rater_prompts.md`.
   Per context: 0–100 similarity to each vignette + a 100-point retrieval split across vignettes.
   Per strategic context (UG/TG × Control/Market): a 100-point receiver-type split
   ("whom do you picture on the other side?").
3. **Record**: long-format workbook `recording_template.csv` (one row per rating) +
   `recording_splits_template.csv` (retrieval and receiver splits).
4. **Analyze**: `04_analysis.py` aggregates vignette ratings to context×category means, computes
   Δsimilarity (Market−Control per game; Aid−Bonus) and correlates with the measured
   Δcategory-shares from `../../replication_package/data/player1_all_categorized.xlsx`
   (the 6 game×comparison cells; receiver shifts from player2). This is the "treatment effect as a
   function of similarity" regression NG proposed in the May thread, at the level the theory
   specifies.

## Contexts (10)

Bonus story; Aid story; Control DG-KW, DG-LT, UG, TG; Market DG-KW, DG-LT, UG, TG.
Texts verbatim from `../../instruments/games_instructions.md` and `stories.md`, collected in
`contexts.md`. (Minimal set if run manually: drop the two LT contexts → 8. The LT rows cost
little via API and discipline the circling-back section §5.2.)

## Key design choices (and why they differ from round 1)

- **Similarity instruction**: raters judge *overall situational similarity* — "considering both
  the structure of the decision and the context in which it takes place" — NOT the May round's
  "structural features only". That restriction suppressed exactly the contextual channel the
  retrieval model runs on (AA's point in the May thread). Round 1 remains the structural
  benchmark; round 2 is the retrieval-relevant measure.
- **Category definitions**: written to match the paper's classification scheme so the similarity
  measure plugs directly into the measured retrieval shares q_c.
  **TODO before running**: reconcile the three definitions in `01_generator_prompt.md` with the
  exact wording of the classification-rules file given to GPT-4.1 (AA has it; not in this repo).
- **Domain balancing**: each category's 8 vignettes span the same 6 domains (workplace;
  family/friends; neighbors/community; strangers/one-off; small business/commerce;
  online/anonymous) + 2 free, so category is not confounded with setting.
- **Generator ≠ raters**: generate with one designated model and document it. If run via API,
  the runner uses a model that is then also a rater — acceptable (raters see only the text), but
  a 4th-model generator is cleaner if run manually.
- **Frozen vignettes**: generated once, reviewed by SN/AA/NG, then identical across all 9 rater
  conversations. Any edit to a vignette after rating starts = restart.

## Hypotheses (pre-specified; mirror `../similarity_survey_design.md` Module A)

H1. Market contexts are more similar to Self-interest and Mutual Benefit/Cooperation vignettes and
    less similar to Moral vignettes than the matching Control contexts, in every game.
H2. Bonus and Aid are close on similarity to Moral vignettes; Aid is more similar to Self-interest
    vignettes (need/scarcity content), Bonus more similar to Mutual Benefit/Cooperation vignettes
    (joint production content).
H3. TG contexts are more similar to Mutual Benefit/Cooperation vignettes than DG/UG contexts,
    already under Control (the cross-game control fact of Figure 2).
H4. Receiver types: under Market, the split shifts toward the accepting (UG) and returning (TG)
    counterpart vignettes relative to Control — the similarity counterpart of the P1 belief shifts.
H5. Across the 6 game×comparison cells, Δ(category share) from the classifications is increasing
    in Δ(context-to-category similarity).

## Execution options

**Protocol as executed (2026-07-19, SN-approved):** generator = Claude Fable 5 (most capable tier
for the constrained one-shot; restores generator ≠ rater within the API path); raters = Claude
Opus 4.8 with adaptive thinking + effort "high" set explicitly (the API default is thinking-off;
this makes the rater a reasoning-tier judge, comparable to the eventual GPT/Gemini reasoning-tier
columns), 3 permutation sets. Category definitions in `01_generator_prompt.md` reconciled with the
classification-rules file (`instruments/prompts_pl1_pl2.docx`) before generation: CLASS S gained
category 3's strategic self-protection prong (4 of 8 vignettes), CLASS C gained category 2's
risk-with-upside clause, banned words extended with "greedy"/"betray".

**Original recommended path for a same-day run (SN, 2026-07-19):** single-model API run on Claude Opus 4.8
— `python3 03_api_runner.py --generate` (review + freeze vignettes) then
`python3 03_api_runner.py --rate --models claude` (3 permutation sets). Estimated cost ≈ $5–10
total at Opus 4.8 pricing ($5/M input, $25/M output; ~200k input + ~10k output tokens per rater
conversation, dominated by the growing conversation history). Treat the single-model result as the
working exhibit; add GPT/Gemini conversations later for the cross-model robustness row before the
paper claims it (the May round's credibility partly rests on 3-model consistency), and the human
survey remains the real validation. Category definitions in the generator prompt follow the
paper's published category descriptions; AA's classification word file is a one-line ask and only
affects the generator — if the wording differs materially, regenerating + re-rating costs a few
dollars, so do not block on it.

- **Manual** (May style): follow `02_rater_prompts.md`; 9 conversations × ~12 messages. Heavy:
  10 contexts × 32 vignettes = 320 ratings per conversation. The reduced protocol (8 contexts,
  6 vignettes/category = 18 + 8 receiver) is ~40% the volume.
- **API**: `03_api_runner.py` runs generation + all 9 rater conversations and writes the workbook.
  Needs ANTHROPIC_API_KEY / OPENAI_API_KEY / GEMINI_API_KEY. Transcripts saved under
  `transcripts/`.
